# T3 Code

The T3 Code driver drives T3 through its MCP orchestration tools. Parrot opens a thread for a session and reads messages, tool calls and pending requests from it.

| Part | Value |
| --- | --- |
| Agent id | `t3` |
| Egg | `aiviarium/t3` |
| Driver | `parrot-driver-t3`, a program in the egg |
| T3 versions | `>=0.1.10, <0.2.0` |
| Controls | `native` |

## Install and connect

```bash
parrot eggs install aiviarium/t3
```

The driver reaches a T3 server in one of two ways:

| Way | Settings |
| --- | --- |
| A running T3 server | `PARROT_T3_URL`, such as `http://127.0.0.1:3773/mcp`, and `PARROT_T3_TOKEN` when it wants a bearer token |
| A command over stdio | `PARROT_T3_MCP` names the program, and `PARROT_T3_MCP_ARGS` adds arguments |

The session option `t3.url` overrides the URL, and `t3.command` or `command` overrides the program. The token comes from the environment only.

## What the driver reports

| Item | Source |
| --- | --- |
| User messages | Thread messages |
| Assistant text | Thread messages |
| Tool calls | T3 tool calls, with their input and result |
| Requests | T3 pending requests, as questions |
| Usage | T3's tools return no figures, so the usage report is empty |

The driver advertises `attachments` for images and files. It advertises no stream, resume, fork or subagent feature, so items arrive as the driver reads the thread.

## Options

| Option | Role | Applies | Values |
| --- | --- | --- | --- |
| `model` | `model` | `next_turn` | The provider instance's models, `default` before the first list arrives |
| `mode` | `mode` | `now` | The T3 runtime modes |

T3 offers four runtime modes. The egg lists the first and last as fallback choices, and the driver maps each mode to a level:

| Mode | Level | Network |
| --- | --- | --- |
| `approval-required` | `read` | No |
| `auto-accept-edits` | `write` | No |
| `auto` | `write` | Yes |
| `full-access` | `host` | Yes |

## Limits

- T3 is a separate product with its own project and provider setup. Parrot does not start or configure it.
- A pending request is read and answered through T3's MCP tools.
- Steering a T3 turn sends the message to the thread in T3's `steer` mode; it does not interrupt the turn.
